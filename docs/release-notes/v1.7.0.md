## Tippani 1.7.0 — Discovery, visuals, local review, and a front door

The release that makes Tippani a place you can *start* — and now *write* — not just a viewer you hand a PR id to. Discovery turns the portal into a home screen, specs finally render their images and diagrams, a branch or a local clone becomes a first-class review surface with private annotations, you can author a whole spec and open its PR without a working tree — and `npx tippani --demo` opens the whole thing with no account at all. From [#68](https://github.com/mavaali/tippani/pull/68), [#69](https://github.com/mavaali/tippani/pull/69), [#70](https://github.com/mavaali/tippani/pull/70), [#71](https://github.com/mavaali/tippani/pull/71), and [#72](https://github.com/mavaali/tippani/pull/72). `npm i -g tippani` now pulls this build.

### Try it with no setup

```bash
npx tippani --demo
```

A sample spec with sample comment threads: no account, no credentials, no clone. Nothing is sent anywhere. Honours `--port` and `--headless`.

### Write specs, not just review them

End-to-end **remote authoring with no working tree**: stage a branch, add or edit `.md` files, stage a PR (optionally linked to a work item), and publish the whole set with one **Push to remote**.

Everything is staged first and crosses the network exactly once. A partial authoring session leaves nothing on the remote, and a branch that moved underneath you is caught before it overwrites newer work. The four authoring tools are `stage_branch` → `stage_spec` → `stage_spec_pr` → `push_staged_changes`.

**"Personal comments" are now "Annotations"** across the UI, the MCP tools, and the docs — fittingly, *tippani* itself means "annotation". Links inside a rendered spec now behave sensibly too: in-root Markdown opens inside Tippani, everything else in your OS browser, and relative doc links no longer 404.

### Discovery — find work without leaving Tippani

Tippani used to have to be *handed* a PR id. Now the portal is where the flow begins, and it lands as MCP tools too, so an agent can run the whole loop through Tippani alone — without a separate Azure DevOps MCP server in the picture.

- **Review queue** — pull requests scoped by **role** (specs I'm reviewing, specs I'm authoring). Cards open the PR *inside* Tippani rather than bouncing out to ADO.
- **Work-item search** — a WIQL query against ADO work items, defaulting to Features from the last month for the current user.
- **Spec search** — full-text search over the specs repo, opening a spec read-only with its review history.
- A faceted Discovery home hosting all three, plus a **Branches** tab (remote and local) and a personal **Reading list**.

### Specs render their visuals

A spec full of broken image icons and raw diagram source is *worse* than opening the file in Azure DevOps, which renders both. That gap is closed.

- **Embedded images render**, including **Git-LFS-backed** ones. Tippani fetches the blob server-side with its own token and streams it with the right content-type — the browser can't do this alone, because an `<img>` GET can't attach an `Authorization` header and ADO's session cookies are `SameSite`. The proxy is limited to image content-types so it can't become a general file-read proxy.
- **Mermaid diagrams render** — locally bundled (no CDN, works offline), theme-aware, and strict-mode. A diagram that fails to parse degrades to its raw code with a note instead of blanking the section. ADO's native `:::mermaid` syntax renders through the same path.

### Review a branch, or a local clone

A pull request is no longer the only unit of review.

- **Local-clone review** reads branches and files straight from a folder on disk — no PR, and no Azure DevOps connection at all (`--local-repo=<path>`).
- **Private annotations** are personal, line-anchored notes on a draft spec, stored on your machine. They carry a content-addressed anchor, so a note **follows its block when the document is edited** — and a note whose block was deleted is marked `stale` rather than silently mispointing at the wrong line.
- **The MCP shim now boots without a token**, in local-only mode. A token that *is* supplied but is the wrong kind still fails fast.

### Approve / Request Changes actually votes

`POST /api/review` used to compute a vote and throw it away: it never called Azure DevOps, always returned `{ok: true}`, and the UI toasted "Approved!" over a no-op. It now records your real vote on the pull request.

Request Changes maps to -5 (waiting for author) rather than -10 (rejected); unknown review types are rejected instead of silently voted; votes are never queued offline, since a stale vote sent later could approve a PR whose content has moved on; and the client reports success only when the server says the vote landed.

### Security

Stored-XSS fix for inline `<script>` data embeds, SVG-XSS neutralized in the image proxy, a DNS-rebind Host allow-list, local reads gated to roots you deliberately opened, a durable annotation store that quarantines corruption instead of silently overwriting it, and symlink-safe working-tree reads with a git timeout.

### Under the hood

CI now runs the full suite on Node 20, 22, and 24 for every push and PR. Six more pure modules extracted out of `index.js` — `html-util`, `ado-read`, `local-git`, `personal-comments`, `personal-comments-store`, and `review-vote` — each with tests. The docs are rewritten: the README is now a User Manual and hub, alongside a full [User Guide](../user-guide.md) and an [MCP & API Reference](../mcp-api.md).
